## Standing rules

- **Language:** all code, UI text, docs and commits in English by default; every UI string also in Spanish behind an EN | ES switch. Talk to the owner in Spanish.
- **Modular:** small files, services split by business area, no monolithic files. Every folder gets an ultra-short English `README.md` (what each file does). Update the folder README in the same change as the files.
- **Rust backend** (owner's standing preference), **MariaDB 11.4** (`infra/compose.yaml`, credentials in `infra/.env`), **TypeScript frontend** (Vite), **Three.js** globe.
- **Secrets:** `env.txt` holds `api.nasa.gov <key>`, `earthdata <token>` and, if the owner added it, `anthropic <key>`. Read them at runtime; never print, log, commit or paste them. `infra/.env` likewise.
- **Contest rules:** cite every source with its license (keep `handbook/en/07-references.md` + `es/` mirror current); non-NASA material must be open; no NASA logos, flags or mission insignia; log every AI assistance in `AI_USE.md`; AI-generated images or video shipped in the product carry a visible "SI-assisted" mark; satellite imagery shown as evidence must be real and licensed (Blue Marble, VIIRS, Landsat, Sentinel-2 with "Contains modified Copernicus Sentinel data [year]"), never AI-generated.
- **Honesty about scale:** every reading carries a source, a date and a badge "field-level" (Sentinel-2/Landsat 10-30 m) or "regional context" (POWER ~50 km, SMAP 9 km, IMERG 10 km, GRACE ~300 km).
- **Pre-diagnosis, never diagnosis:** the UI and the consultant always say so and send the user to an agronomist.
- **Git:** commit after each working milestone with a clear message ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, push to `origin` (private repo `OutWorldDebourer/field-shift`). Never make the repo public, never force-push.
- **Never without the owner:** creating accounts, entering payment data, buying, claiming the GoDaddy/Porkbun domain, creating Google Cloud resources, making anything public, sending messages. Leave these for the morning in "Needs the owner".
- **Verify, don't assume:** run what you build (cargo test / cargo run, npm run build, the browser pane) before marking a step done. Use the `impeccable` skill for UI work; the approved hero image stands in as the approved comp.
- **Design audit gate (owner's rule):** every UI surface (index with globe, field selection, analysis workspace, dashboard, technical sheet) is audited by a separate, fresh auditor agent (model `opus`, the shipped `impeccable-finish-reviewer` as its base) that never sees the build conversation. It receives real desktop (1440 px) and mobile (390 px) screenshots, the two approved images and the surface's design contract, and scores it out of 10: fidelity to the approved direction 2, clarity for the farmer 2, visible working functionality 1.5, phone and desktop 1.5, accessibility and outdoor legibility 1, data honesty (source, date, field/regional badge, pre-diagnosis notice) 1, polish and performance 1. A surface passes only at **8.5 or more with no criterion below half its points**. Cycle build → audit → fix → re-audit, **at most 3 audit rounds per surface**; if it still fails, log its score and missing items in the Decision log, continue with the next milestone, and list it under "Needs the owner". Record every round's score in `design-directions/audit-log.md`.

## Milestones (in order; ship each before starting the next)

1. **Backend skeleton** `backend/` (Cargo workspace): axum HTTP API, config from env.txt/infra/.env, MariaDB via sqlx with migrations (`analyses`, `fields` with a POLYGON column, `messages`, `photos`, `sections`, `reports`, `source_cache`), health endpoint, CORS for the dev frontend.
2. **NASA POWER service:** daily series 1981→today for a point; 40-year normals computed from the daily series; derived indicators: temperature anomaly, heat-stress days, frost days, rain and extremes, FAO-56 reference ET (Penman-Monteith from POWER inputs) and a simple water balance, growing degree days and pest generations for a small pest table (aphid, whitefly, fall armyworm; cite the thresholds used). Cache responses in `source_cache`.
3. **Imagery and terrain:** Planetary Computer STAC search (Sentinel-2 L2A + Landsat C2 L2) for the field polygon, NDVI time series for the polygon (anonymous SAS token), bare-soil periods; NASADEM slope for the polygon.
4. **Earthdata sources:** SMAP L4 surface/root-zone moisture (cloud OPeNDAP, range syntax `[a:b]`), IMERG Late daily rain (GES DISC OPeNDAP, order [time][lon][lat]), GRACE series (reuse `tools/grace_point.py` logic or pre-extracted JSON per example site). Bearer token from env.txt.
5. **Climate projection:** NEX-GDDP-CMIP6 on Planetary Computer. First confirm each model's license on NASA's page; use only open-licensed models; record it in references.
6. **Evidence package + open crop knowledge (owner's rule: the farmer names ANY crop, no closed list):** the farmer types the crop or shows it in a photo (grapes, strawberry, mango, pineapple, anything); the consultant normalizes it to a crop record (common name, scientific name, botanical family, crop type: annual / semi-perennial / perennial). A small verified seed knowledge base (cited per field: Kc, water need, temperature thresholds, legume N, pests with published degree-day thresholds, beneficial insects and fungi such as Trichoderma, Chrysoperla, Beauveria) answers known crops instantly; any other crop gets a trait card researched by the analyst stage from open sources with the Claude web search tool, every value with its citation, stored in MariaDB for reuse and labelled "AI-researched, verify". A value without a source is an information gap, never a guess; pest generations are computed only where a published threshold exists, otherwise guidance is qualitative. Crop type drives the advice: annuals get the three-strategy rotation comparison (current + 2) scored on soil, water, pest break, income and risk with why/evidence/gaps/risks; semi-perennials (pineapple, strawberry) get what to plant at renewal plus interim cover; perennials (grape, mango, avocado, citrus) never get "rotate the main crop": they get inter-row cover crops and green manures, intercropping, residue management and biological control. The UI offers suggestions while typing, never a restriction.
7. **Frontend index:** Vite + TypeScript, frosted-glass panels, sections per `index-prompts.md`, EN | ES switch. **The globe is delegated (owner's rule) to a dedicated subagent with `model: "fable"` (Claude Fable 5.2) and `effort: "high"`**, briefed with: Three.js globe at sunrise with real NASA textures (Blue Marble, VIIRS night lights) and an atmosphere rim, moving sun terminator, scroll-driven dive orbit → valley → field, the lock-on reticle, corner instruments, reduced-motion and low-power fallback to a still frame, the two approved images as the visual bar, delivered as an isolated `frontend/src/globe/` module with its README that the index and app import. The Lemo-Opuscar Satellite Briefing demo engine (`C:/Users/OutWorldDevourer/.claude/plugins/marketplaces/lemolab/styles/satellite-briefing/demo/engine.js`, MIT, © 2026 Lemomo/LemoLab) may be adapted; keep its copyright notice and cite it. Do not copy its STYLE.md text (CC BY-NC). The globe then goes through the design audit gate like any surface.
8. **App:** field selection (My GPS | Example site; point or drawn polygon with area; place search), workspace with the glass chat (up to 10 photos per message, drag and drop on desktop, camera on phone) and the section column (Your field, Soil, Pest care, Nutrition, Rotation, Technical sheet) with states empty / in progress / ready / with gaps; dashboard tab; same features on phone and desktop.
9. **Consultant:** Claude via the Anthropic Messages API with model `claude-opus-5-5` (key: `anthropic` line in env.txt, validated 2026-11-14), vision input for photos, tool use to request the evidence package and to emit structured section updates; system prompt as a friendly agronomy consultant that asks for missing data one or two questions at a time, guides photos, accepts "I don't know" as a gap, and may only cite numbers from the evidence package. Read the `claude-api` skill before writing this code. Keep it behind a provider interface and also ship a clearly labelled scripted demo mode for the example site, as a fallback if the API fails during judging. Rate-limit per visitor so the public demo cannot drain the credit.
10. **Export:** technical sheet PDF with all readings, sources, dates and licenses; CSV of the series; share link.
11. **Example sites:** Huaral valley (Peru) fully precomputed and cached so the demo works even if a service is down; one U.S. site if time allows (then add SSURGO/CDL).
12. **Docs:** keep the handbook (EN + ES) current: data sources page, references page with licenses, how it works, AI use. Rebuild with `node handbook/build.mjs`.
13. **Demo film and hero loop (only after the app works):** with the `lemo-opuscar` skill, a film of 30 seconds or less that opens in the Satellite Briefing grammar (orbit → dive → lock-on on the Huaral field, real imagery) and continues in the Mascot Screencast grammar recording the real app (cursor = farmer, reticle = software), following `design-directions/storyboard-lemo-prompts.md`; English subtitles; a visible "SI-assisted visuals" mark; a credits list. Cut an 8-12 s silent loop from the opening for the index background (MP4 + WebM, 2-4 MB, still-image fallback).
